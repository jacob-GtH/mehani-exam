# منصة التدريب على اختبارات الاعتماد المهني

Next.js + TypeScript + Tailwind + Sanity. مبنية للنشر على Vercel.

## المتغيرات المطلوبة

أنشئ ملف `.env.local` في جذر المشروع (ولا ترفعه إلى GitHub):

```
NEXT_PUBLIC_SANITY_PROJECT_ID=رقم مشروع Sanity
NEXT_PUBLIC_SANITY_DATASET=production
SANITY_WRITE_TOKEN=توكن بصلاحية Editor (سري)
NEXT_PUBLIC_SITE_URL=https://دومينك.com
ADMIN_PASSWORD=كلمة مرور طويلة للوحة التحكم
ADMIN_SECRET=نص عشوائي طويل 32 حرفًا فأكثر
```

> `SANITY_WRITE_TOKEN` و`ADMIN_PASSWORD` و`ADMIN_SECRET` أسرار: لا تضعها في الكود ولا في GitHub.

## التشغيل محليًا

```bash
npm install
npm run seed      # اختياري: ينشئ اختبارًا تجريبيًا واحدًا
npm run dev       # http://localhost:3000
```

## لوحة التحكم

- الدخول: `/admin` (الرابط غير ظاهر للزوار عمدًا).
- **الاختبارات:** إنشاء وتعديل ونشر وحذف، وإدارة الأسئلة واحدًا واحدًا.
- **استيراد:** لصق أسئلة من Word أو Excel لعدة اختبارات دفعة واحدة (زر «ضع القالب الجاهز» يوضح الصيغة).
- **الإحصاءات:** المحاولات ونسب النجاح وأصعب الأسئلة.
- الاختبار الجديد يبقى **مسودة** حتى تفعّل «منشور» من صفحته.

## النشر على Vercel

1. ارفع المشروع إلى مستودع GitHub.
2. في Vercel: Add New → Project → اختر المستودع.
3. في Environment Variables أضف المتغيرات الستة أعلاه، مع جعل `NEXT_PUBLIC_SITE_URL` هو دومينك الحقيقي.
4. اضغط Deploy.
5. من Settings → Domains أضف دومينك واتبع تعليمات DNS.
6. أعد النشر (Redeploy) بعد تغيير أي متغير.

## بعد النشر (للظهور في جوجل)

1. سجّل الموقع في Google Search Console (Domain property).
2. أرسل `https://دومينك.com/sitemap.xml` من قسم Sitemaps.
3. اطلب فهرسة الصفحة الرئيسية وصفحتين أو ثلاث من الاختبارات.
4. غيّر `SITE.name` في `src/lib/site.ts` إلى اسم فريد غير عام.
5. اكتب في كل اختبار وصفًا فريدًا من لوحة التحكم، وأضف عددًا جيدًا من الأسئلة.

## المرحلة الرابعة: تحسينات أمنية أولية

- إضافة تحديد معدل لمحاولات إرسال نتائج الاختبارات حسب عنوان IP (8 طلبات/دقيقة).
- التحقق من بنية البيانات، والـ slug، ونمط الاختبار، ومدة المحاولة، ومفاتيح الأسئلة، ومنع تكرار السؤال أو إرسال خيار غير موجود ضمن خياراته.
- إجراء احتساب النتيجة على الخادم اعتماداً على بيانات Sanity، وعدم قبول درجة أو إجابة صحيحة يرسلها العميل.
- إضافة حد أولي لمحاولات تسجيل دخول الإدارة (5 محاولات/15 دقيقة) وحد أقصى لطول كلمة المرور.
- ملاحظة تشغيلية: محدد المعدل الحالي في ذاكرة عملية Node.js، لذا فهو دفاع أولي فقط ولا يغني عن محدد مركزي مثل Redis/KV في النشر متعدد النسخ أو Serverless.

### نقاط أمنية لم تُغلق بعد

- صفحة بدء الاختبار ما زالت تجلب `correct` و`explanation` ضمن بيانات تُمرر إلى مكوّن العميل؛ لذلك يمكن للمستخدم التقني استخراج الإجابات من استجابة الصفحة. يلزم نقل جلسة الاختبار والتصحيح/المراجعة إلى الخادم في خطوة مستقلة قبل اعتبار بنك الإجابات محمياً.
- يلزم ضبط محدد معدل مركزي موثوق، وإضافة حماية من CSRF/الطلبات الآلية وفق منصة الاستضافة، واختبار مسارات الإدارة والاختبار بعد ضبط متغيرات البيئة.
- لم يُنفذ بناء إنتاجي في بيئة العمل الحالية لغياب ملفات Next/TypeScript التنفيذية في `node_modules`.

## المرحلة الخامسة: عزل مفاتيح الإجابات على الخادم
- صفحة بدء الاختبار لا تستعلم عن الأسئلة الكاملة؛ تعرض بيانات التعريف فقط، وتطلب جلسة من `/api/exam-session` عند البدء.
- ينشئ الخادم ترتيب الأسئلة والخيارات، ويحتفظ بمفتاح الإجابة والشرح داخل حمولة مشفرة AES-256-GCM. وثيقة الجلسة في Sanity تحتوي النص المشفر فقط ولا تحتوي الإجابات الصريحة.
- وضع المحاكاة لا يرسل أي مفتاح إجابة أو شرح إلى المتصفح قبل التسليم. التصحيح النهائي ومدة المحاولة ودرجة النجاح تُحسب على الخادم.
- وضع التدريب يطلب التصحيح من endpoint منفصل بعد اختيار المستخدم للإجابة، ولا تُرسل الإجابة الصحيحة قبل الاختيار.
- التسليم يستخدم معاملة Sanity واحدة لإنشاء المحاولة وإغلاق الجلسة، مع فحص `_rev` لمنع قبول تسليمين متزامنين للجلسة نفسها.

### إعداد مطلوب قبل النشر
أضف متغير بيئة خادميًا باسم `EXAM_SESSION_SECRET` بقيمة عشوائية قوية لا تقل عن 32 حرفًا. لا تستخدم بادئة `NEXT_PUBLIC_` ولا تضع السر في المستودع. يتطلب هذا المسار أيضًا `SANITY_WRITE_TOKEN` بصلاحية قراءة وكتابة وثائق الجلسات والمحاولات. وثائق `examSession` مشفرة، لكن يوصى بتقييد صلاحيات dataset وتهيئة سياسة تنظيف دورية للجلسات المنتهية.

### مطلوب قبل النشر

1. اضبط `NEXT_PUBLIC_SITE_URL` على عنوان النطاق الحقيقي، دون مسار إضافي، ثم أعد النشر. لا تترك القيمة الافتراضية `http://localhost:3000` في الإنتاج.
2. افتح `https://YOUR-DOMAIN/sitemap.xml` وتأكد من ظهور الصفحة الرئيسية والدليل وصفحات الاختبارات المنشورة.
3. أضف النطاق إلى Google Search Console، ثم أرسل `sitemap.xml` واطلب فهرسة الصفحة الرئيسية وصفحة الدليل وصفحات الاختبارات المهمة.
4. أضف لكل اختبار وصفاً أصلياً ودقيقاً من لوحة التحكم. لا تستخدم وصفاً عاماً مكرراً، ولا تضف شروطاً أو معلومات رسمية عن اختبار ما لم تتحقق منها لدى الجهة المنظمة في اليمن.
5. الدليل الحالي إرشادي عام؛ ينبغي إضافة أدلة متخصصة لكل مهنة بعد تزويدنا بمعلومات موثوقة عن الاختبارات والجهات المنظمة ومتطلباتها في اليمن.

**التحقق:** لم يكتمل `npm ci` في بيئة الفحص بسبب انتهاء مهلة التنفيذ، لذلك لم يتم تشغيل `next build` أو فحص TypeScript. يجب تنفيذ `npm ci` ثم `npm run build` في بيئة المشروع قبل النشر.
